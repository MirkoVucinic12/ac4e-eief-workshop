# Demo — C11 review, C12 Goals, C13 Acceptance criteria, C14 Verification, Capstone

**When:** Fri 27 Nov 2026, 14:00–16:30 (Rome).
**Example:** the synthetic Card–Krueger panel.

## C11 Review what the swarm returned (14:00–14:10)

For each pull request linked to a lunchtime card:

```text
Use the pr-reviewer sub-agent on pull request #<N>. Read only.
Check it against AGENTS.md and the issue's acceptance criteria.
List blockers first.
```

Read the list of changes yourself. Move the card to `done` (merge) or back to `ready` with a comment.

## C12 Goal (14:10–14:25)

**Say:** one sentence describing the finished state, in a form you can check. Where to stop, not how to get there. The satnav destination.

Example:

```text
/goal notes/replication_audit_ck.md exists and records GREEN, YELLOW or RED with the test output
```

Claude Code and Codex: `/goal …`. Cursor: put the sentence as the last line of the prompt ("Stop when …"). More examples: [`examples/card-krueger-goals/goals/`](../examples/card-krueger-goals/goals/).

Participants rewrite one lunchtime card's vague title as a one-sentence goal.

## C13 Acceptance criterion (14:25–14:50)

**Say:** a yes/no check that says when the job counts as done. A building inspector's checklist. Each agent knows when to stop; you check many results fast.

Example criteria for `ck-data-cleaning`:

- [ ] `examples/card-krueger-toy/data/toy_fast_food.csv` is unchanged.
- [ ] The check command passes.
- [ ] The README states the sample restriction.
- [ ] The DiD printed by `did_analysis.py` equals the DiD written in the note.

Participants add 3 criteria to one card, relaunch it, and judge the new pull request only against them.

## C14 Verification and evaluation (14:50–15:50)

**Say:** three parts. Need less checking (small jobs, protected files, clear done-when checks). Automate the rest (a check command). Then test your Skills, sub-agents and whole set-up against known mistakes, like planting an error in a paper to test a referee.

**1. Green first.** Run the check command:

```bash
python3 -m pytest examples/card-krueger-toy/tests examples/mini-economics/tests
```

**2. Planted fault.** On a temporary separate copy (`fault-drill`), ask:

```text
Check examples/card-krueger-toy/faults/drifted_table.tex against the numbers
the code produces. Run this and explain the error:
PYTHONPATH=examples/card-krueger-toy/src python3 -c "from pathlib import Path; from panel_workflow import run_robustness_suite, verify_latex_table_numbers; verify_latex_table_numbers(Path('examples/card-krueger-toy/faults/drifted_table.tex').read_text(), run_robustness_suite())"
Do not edit tests or anything in faults/.
```

Expected: `ValueError: LaTeX table drift: with_perm_closed DiD 3.15 != 2.6364`. The table was copied by hand.

**3. Fix and rerun:**

```text
Write a corrected table to notes/fault_drill_table.tex, generated by the code
(render_latex_booktabs_table), not typed by hand. Check it with
verify_latex_table_numbers, then rerun the check command.
```

Never edit files in `faults/`: the automatic checks rely on them staying wrong.

**4. Score the set-up** in [`notes/verification_scorecard.md`](../notes/verification_scorecard.md):

| Tested | How | Caught? |
| --- | --- | --- |
| Skill | Run `replication-checker` with the drifted table in view | |
| Sub-agent | Run `data-reviewer` on `faults/unbalanced_panel.csv` | |
| Whole set-up | Fresh chat, fresh copy: can it reproduce DiD = 3.0 from the README alone? | |

**Optional:** show the automatic step after each edit, [`.claude/hooks/post_edit_did_analysis.py`](../.claude/hooks/post_edit_did_analysis.py), which reruns the Card–Krueger checks whenever the agent edits `did_analysis.py`.

**Say:** passing checks show the code does what it says, not that the design is identified.
